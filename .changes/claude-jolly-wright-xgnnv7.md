- The agent's kernel is now a Scheme interpreter built into Prime Agent: the model works through one `eval` tool, sessions run inside the daemon (a new session's first call is about three times faster on a running daemon), nothing installs Python or uv any more, and a crashed session or daemon is shown, restarted and resumed automatically. Python skills and the Python REPL are gone; saved sessions still open.
- A new session in a project you have used before starts its first turn sooner: the workspace checkpoint re-reads only the files that changed instead of every file.
- `fs-read` now pages the file's likely next reads (its test file, its imports, and its callers from the symbol index) out as handles named in the result, so the model can read a neighbour with `ctx-page` without another lookup; per project it learns whether those handles get used and scales the prefetch down when they do not.
- Paged-out and thinned outputs now preview their most informative lines instead of just the head and tail: error/warning/failure lines and their locations, the first occurrence of each distinct line with repeats folded into `×N`, and lines with rare tokens, within the same budget; per project it learns which line patterns are always noise (banners, progress bars, timestamps) and folds them into one marker.
- The agent can drive the Rizin reverse-engineering framework you have installed: `(rz-open "/path/binary")` starts a `rizin` session, `(rz-cmd s "pdf @ main")` and `(rz-cmdj s "aflj")` run its commands (analysis, disassembly, RzIL, patching, and the debugger with `#:debug #t`), and `(api-help "rizin")` maps them. A command is interrupted when its time limit passes or its cell is stopped, and every session and the program it debugs is killed when the kernel ends. It needs `rizin` 0.7.4 or newer on your PATH; without it `rz-open` says how to install it.
- A distribution build's first launch imports the official configuration again: starting up no longer creates the agent directory before that import runs.
- The agent's `bash` commands now run on a bash-compatible shell built into Prime Agent on Linux, macOS and Windows, instead of starting `/bin/bash` for each one: `ls`, `cat`, `grep`, `sed`, `find`, `sort`, `xargs`, `jq` and 27 more utilities run inside it, only the programs a command names (`git`, `cargo`, ...) are started, a short command returns sooner, and `bash` and `jq` work on a machine that has neither (Windows without Git Bash). Scripts that depend on the system shell (signal traps, `$$` as a process id, `ulimit`) can have it back with `"shell": "system"` in settings; a `shellPath` you already set keeps selecting your shell.
- A misspelt option no longer does nothing: the agent's kernel functions refuse an option they do not accept (`#:timout-ms` for `#:timeout-ms`, an unknown key of a `bash` or `fs-*` options hash, an argument an MCP tool's schema does not list), an option given twice or without a value, and a wrong number of arguments, before anything runs, and the error names the accepted options and the nearest one so the agent corrects the call in one step.
- `rlm-collect` no longer hangs past its timeout: it reads what each subagent has already reported instead of asking every subagent in turn, so a snapshot returns at once however many are busy, a wait ends at its `#:timeout-ms` (it used to run about 5 seconds over), and a wait ends early, marking the row `waiting_on_you`, when a subagent is itself waiting for a message from the session that is collecting it. A subagent that runs for hours is no longer cut off as unreachable by the waits its parent left behind.
- The agent's kernel cells read better in the transcript: a cell's title names what it does (`fs-read src/main.rs`, `bash · cargo test`) instead of its first line and keeps its duration on screen, its Scheme code is syntax-highlighted, a command's output and a file's text show as text rather than as an escaped `#<hashmap {...}>` dump, a failed command shows its exit code and a failed cell its error message on the title, a cell or command still running in the background is marked as such instead of as done, an edit no longer repeats its confirmation under its diff, and a diff now shows trailing-whitespace and line-ending changes that used to look like two identical lines.
- Commands and Rizin sessions no longer go wrong at their end on a busy machine: with `"shell": "system"`, a short `bash` command's output could end in an internal `prime-agent-complete:` marker and a large output could lose its `out:` handle; an interrupt that reached rizin while it was starting a `!command` was lost, so rizin was killed two seconds later and its session with it, and is now sent again until the command ends; a session that crashed while a cell waited for a command logged a second fault from that cell; and `factory-run` on a machine whose states name one stored subagent reads the harness store once, not once per state.
- The panels read alike: every list names its arrows `↑/↓ navigate` and an empty list no longer offers keys that do nothing; text cut to fit ends in `…` instead of stopping mid-word (table cells, titles, session names, errors), and a long session name no longer pushes the spend off the top bar; a confirm question wraps instead of being cut; durations roll over (`1h 11m`, not `71m 05s`) in the bash, factory and goal views; the agents view keeps its session list on a short terminal and the splash no longer holds blank rows on a narrow one; the `/settings` tab strip shows that more tabs exist on a narrow pane; the `/better` and side-question notices name the key you actually bound; and the heartbeats view says when its list failed to load instead of reporting none.
- A macro in a kernel cell can no longer do what the cell itself may not: the body of a `defmacro` or `syntax-case` macro used to run where Steel's own process, environment, file-loading and engine builtins were still open and its output went to the daemon's log; it is now as closed as the cell, prints into the cell's output, and a macro body that loops stops when its cell is stopped.
- One session's kernel can no longer write into another's: Steel's own modules, documentation table and will executor were one object in every session of a daemon, so a name a cell added to a builtin module or a value it put in Steel's internal boxes was read by every other session. Each session now has its own, `(command-line)` no longer returns the daemon's arguments, and `(#%gc-collect)`, which grew the daemon's memory with every call, is closed.
- A kernel cell that asks Steel for an impossible size or sends the host a number JSON cannot carry now gets an error instead of taking its session, or the daemon, down: `(read-bytes 100000000000 port)`, `range-vec` and `make-immutable-vector` are limited like `make-string`, a negative count (`(make-string -1 #\a)`) is refused, and so is an infinity or not-a-number on its way to the host. `(make-vector 2 100000000)` works: the fill value was mistaken for a count.
