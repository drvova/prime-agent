- Large subagent fan-outs no longer start every child at once: worker spawns for `rlm.spawn` / `rlm.create_session`, kernel starts, and crash recovery now share one daemon-wide boot budget that widens while boots stay fast and narrows under CPU or memory pressure, with the foreground session's boots served first. A spawn that waited says so in its handle (`queued_ms`), and `rlm.collect` results report a child's boot queue time. `PRIME_AGENT_MAX_CONCURRENT_KERNEL_BOOTS` still pins the width. No new settings.
