# events: event sources, publications, and subscriptions

The daemon keeps one event bus for every session it runs. An event source is a service with a schema: a name (`deploy.finished`) and a JSON object schema for its payloads, owned by the session that defined it, which is the only session that publishes or removes it. A session that subscribes gets a new turn for each matching event, so it reacts instead of polling: start the work, subscribe to the event that ends it, and end the turn. Sources and subscriptions persist across daemon restarts; a subscription whose session no longer exists is dropped at its next event. The bus needs the daemon: in a daemonless run these functions raise.

- `(event-source-define name schema #:description)`: define, or redefine, a source this session owns; the record `{name, description, schema, ownerSessionId, ownerName, definedAt, publishedCount}`. `name` is 1 to 64 lowercase letters, digits, `.`, `-` and `_`, starting with a letter. `schema` is a JSON object schema as a hash (`(hash 'type "object" 'properties (hash 'env (hash 'type "string")) 'required (list "env"))`), at most 16 KiB. Another session's source cannot be redefined. A session owns at most 32 sources
- `(event-source-remove name)`: remove one of this session's sources and every subscription to it: `{removed, subscriptionsRemoved}`
- `(event-publish source payload)`: publish one event of a source this session owns: `{eventId, matched}`, where `matched` counts the subscriptions it is delivered to. `payload` is a hash checked against the source's schema (an invalid one raises with the validation errors, and nothing is delivered), at most 8 KiB as JSON. The call does not wait for the deliveries; each subscription's `deliveredCount` (`event-list`) counts what reached its session. Your own subscriptions never receive your own events
- `(event-subscribe source prompt #:filter #:delivery-mode #:label)`: subscribe this session to a defined source; the subscription `{id, source, filter, prompt, deliveryMode, label, sessionId, cwd, createdAt, deliveredCount}`. Each matching event starts a turn that reads `[agent-message from event:<source>]` followed by the event id, `prompt` (at most 4,000 characters), and the payload as JSON. `#:filter` is a hash of payload keys and the values they must equal (`(hash 'env "prod")`), naming only properties the schema declares. `#:delivery-mode` is `"follow_up"` (the default: after a running turn) or `"steer"` (into it, at its next step). A saved session that is not running is woken for its event. A publisher that wakes the same idle session too often is refused by that session's wake budget, as agent messages are. A session holds at most 64 subscriptions
- `(event-unsubscribe subscription)`: cancel one of this session's subscriptions, by id or by the record `event-subscribe` returned; the cancelled subscription
- `(event-list)`: every source on the bus and this session's subscriptions: `{sources, subscriptions}`
