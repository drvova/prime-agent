# fs: read, search, and edit files

Native, in process, with ripgrep's engine: regex syntax, `.gitignore` rules, globs, and file types behave as in `rg`, on every platform. Prefer these over `rg`/`grep`/`find`/`cat`/`sed` through `bash`: results are structured and capped, and paths resolve against the session's working directory and print relative to it. Every result has a `'text` field, the readable rendering: `(displayln (hash-ref result 'text))`. Options are one hash; an unknown option raises.

- `(fs-read path [options])`: a file's lines under edit anchors: `{path, start, end, total-lines, lines, truncated, line-ends, encoding, final-newline, text}`. `lines` holds `{line, anchor, text}` rows; `text` is a header (`path (lines 1-40 of 120)`) and `LINE:abc|text` rows, where `LINE:abc` is the anchor (line number, then a hash of the line and its neighbours). Options: `'start`, `'end` (1-based, inclusive); at most 2000 lines unless `'end` asks for more. Binary and non-UTF-8/UTF-16 files raise. A whole-file re-read of a file already seen shows `unchanged since turn N` or a diff under fresh anchors, with a handle to the full view for `ctx-page`; `lines` always holds every line
- `(fs-anchor view line)`: the anchor of 1-based `line` of an `fs-read` view
- `(fs-edit path edits [options])`: one atomic patch of anchored edits, so old text is never retyped. `edits` is one hash or a list of them: `(hash 'replace anchor 'text new)`, a range `(hash 'replace (list first last) 'text new)` (inclusive), `(hash 'delete anchor)` or `(hash 'delete (list first last))`, `(hash 'insert-after anchor 'text new)`, `(hash 'insert-before anchor 'text new)`, `(hash 'append text)` (the end of the file; also fills an empty file). An anchor is the string from `fs-read`, or a row of `lines`. `text` is the new lines, one string or a list of strings; line endings, final newline, and encoding stay the file's. All anchors address the file as read (numbers never shift within a patch); edits may not overlap. Returns `{applied #t, path, edits, removed, added, total-lines, hunks, check, text}`: `hunks` and `text` show the changed regions under fresh anchors to chain the next edit from; `check` is the edited file's check (ruff or py_compile, `cargo check`, `tsc`, `go vet`, when one applies and ends in time) or `#f`. Every anchor must still match the file, or the whole patch is rejected and nothing is written: the error lists the stale anchors and the current lines under fresh anchors; retry from those. With the option `(hash 'on-stale 'return)` a rejection is returned (`{applied #f, stale, lines, text}`) instead of raised
- `(fs-write path text)`: create the file, or replace all of it, with `text` (written as given; missing directories are created; the write is atomic): `{path, created, total-lines, bytes, check, text}`. `fs-edit` and `edit` change existing files only; change part of a file with them, not by rewriting it
- `(edit path old-str new-str)`: replace one exact, unique occurrence of `old-str`: `{path, start-line, check, text}`. Raises when `old-str` is missing (the error says where it diverges from the file) or occurs more than once. Prefer `fs-read` and `fs-edit`: no old text to retype, and a stale file is rejected instead of corrupted
- `(fs-grep pattern [options])`: `{matches, files-searched, files-matched, truncated, unreadable, text}`; each match is `{path, line, column, text, extra-lines, before, after}`, and `text` is ripgrep-style (`path`, then `line:text`, context as `line-text`). `truncated` means more matches exist. Options: `'path` (default `"."`), `'glob` (an `rg -g` glob or a list: `"*.rs"`, `"!target/**"`), `'type` (an `rg -t` name or a list: `"rust"`, `"py"`), `'case` (`"sensitive"`, `"insensitive"`, `"smart"`), `'literal`, `'word`, `'multiline`, `'context`, `'before`, `'after`, `'hidden`, `'gitignore` (default `#t`), `'max-results` (default 100), `'max-per-file`, `'max-columns` (default 300)
- `(fs-glob pattern [options])`: paths matching a glob (`"**/*.rs"`): `{entries, truncated, text}`, each entry `{path, kind, size}`. Options: `'path`, `'hidden`, `'gitignore`, `'max-results` (default 500)
- `(fs-find [options])`: entries by file name, like `find -name`; the same result as `fs-glob`. Options: `'name` (a glob: `"Cargo.toml"`, `"*.md"`), `'kind` (`"file"`, `"dir"`, `"symlink"`), `'ignore-case`, `'max-depth`, `'path`, `'hidden`, `'gitignore`, `'max-results`
- `(fs-symbol name [options])`: where one identifier is defined and used, from a per-project index kept in the background: `{name, definitions, references, truncated, partial, text}`; each location is `{path, line, text}`, a definition also `kind` and `handle` (its source, for `ctx-page`). `partial` means the index is still building. Option: `'max-references` (default 50)
