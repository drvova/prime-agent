# rizin: reverse engineering with the installed Rizin

`rz-*` drives the `rizin` program on the user's PATH (0.7.4 or newer; this page was checked against 0.9.1): disassembly, analysis, RzIL, patching and debugging of binaries the user owns or is authorized to examine. Each session is its own `rizin` process fed over a pipe, so a crash in rizin ends only that session. Without rizin on PATH `rz-open` raises one error that says how to install it: pass that to the user, do not try to install it. Everything rizin does is a command string: the functions only open sessions and carry commands, and this page is the map of the commands. `(rz-cmd s "<cmd>?")` prints rizin's own help for any command or prefix (`a?`, `afl?`, `pd?`) and `(rz-cmd s "?*~word")` searches all of it; trust that over memory, since commands differ between rizin versions and from radare2 (`?e`, `?v`, `aer`, `psz`, `s-`, `fs` alone, `afl*` do not exist here).

- `(rz-open target #:write #:debug #:args #:arch #:bits #:base #:raw #:analyze #:stdin #:flags #:timeout-ms)`: start a rizin on `target` (a path, a URI such as `"malloc://512"` or `"gdb://host:port"`, a pid with `#:debug #t`, or `"--"` for no file) and return the session `{session, target, pid, version, debug, write, alive, reason, output}`; `output` is what rizin printed while loading. `#:write #t` opens the file for writing (`-w`; patches hit the file at once). `#:debug #t` starts the program under the debugger (`-d`) with `#:args` (a list of strings); its stdin is empty unless `#:stdin` names a file, and its output arrives in the reply of the command that ran it (`dc`). `#:arch`, `#:bits`, `#:base` override the file's own (`-a`, `-b`, `-B`), `#:raw #t` skips binary parsing (`-n`), `#:analyze #t` runs `aaa` before returning (`-A`). `#:flags` (a list of strings) are further `rizin` options: `(list "-e" "asm.syntax=att")`, `-m addr`, `-k os`, `-p project.rzdb`, `-i script.rz`, `-R directive` (rz-run). `#:timeout-ms` (default 120000) bounds the load
- `(rz-cmd session command #:timeout-ms)`: run one command line and return what it printed as a string, its errors and warnings included (rizin reports a failed command only as text: read it). Join commands with `;` (one line, at most 8 KiB). A reply over 768 KiB keeps its start and end around an `[out:<id> ...]` marker `output-read` and `output-grep` page; narrow such a command with `~`, a count, or a JSON form instead. `#:timeout-ms` (default 120000, `#f` for none): when it passes, or the cell is stopped, the command is interrupted as Ctrl-C would and the session stays usable; a rizin that does not stop within 2 s is killed and the session is dead
- `(rz-cmdj session command #:timeout-ms)`: run a command's JSON form (`ij`, `aflj`, `pdfj`, `izj`, `axtj`, `drj`, `dmj`) and return the parsed value: hashes keyed by rizin's own names as symbols (`(hash-ref info 'bin)`), lists, `#f` for null and for no output. Warnings printed before the JSON are dropped; a reply that is not JSON raises with its text. Integers stay exact up to 2^64-1 (a register holding -1 reads 18446744073709551615)
- `(rz-sessions)`: this kernel's sessions, each `{session, target, pid, version, debug, write, alive, reason}`; a dead one stays listed with `reason` (how rizin ended, its exit status and last output) until closed
- `(rz-close session)`: kill the session's rizin and what it started (a program it debugs; a process it attached to keeps running): `#t`, or `#f` when there is no such session. Every session is closed when the kernel ends; sessions do not survive a kernel restart

A session is the hash `rz-open` returned, or its `session` id. Typical start: `(define s (rz-open "/path/bin"))`, `(rz-cmd s "aaa")`, `(rz-cmdj s "aflj")`, `(rz-cmd s "pdf @ main")`.

**Command grammar.** `cmd[~grep][@ addr]`: `@ addr` runs at a temporary seek (`pd 10 @ main`, `@ sym.imp.puts`, `@ entry0+4`, `@ rsp` in the debugger); `@!n` sets the block size, `@e:k=v` a config value, `@a:arm:32` the architecture, for that one command. `@@` iterates: `afi @@F` (all functions), `@@f:sym.*` (flags by glob), `@@=a1 a2`, `@@c:cmd`, `@@/x 9090` (search hits). `~word` greps lines, `~!word` negates, `~:2..5` picks lines, `~[0]` a column, `~?` counts. Suffix forms: `j` JSON, `q` quiet, `t` a table that `:spec` filters and formats (`aflt:name/cols/nbbs:nbbs/gt/5:json`; `:?`). An argument that contains `;` needs quotes (`wa "nop;ret"`), since `;` separates commands; `|` pipes to a shell command and `> file` redirects. `%v expr` evaluates (`%v 0x10+4`, `%v $$` for the current seek). Interactive modes (`V`, `v`, `~..`, `ee`) do nothing useful here, and `~{...}` JSON grep is unreliable: use `rz-cmdj` and Scheme. `e` reads and sets config (`e asm.syntax=att`, `e asm.bytes=true`, `e search.in=io.maps`), `el~word` lists variables with their descriptions.

**Information (`i`).** `i`/`ij` file summary, `iI` binary info (arch, bits, canary, nx, pic, relro), `ie` entrypoints, `iM` main, `iS` sections, `iSS` segments, `ii` imports, `iE` exports, `is` symbols, `il` libraries, `ir` relocations, `iz` strings in data sections, `izz` in the whole file, `izx` strings with xrefs, `ic` classes, `ih`/`iH` headers, `iR` resources, `iC` signature, `ix` source lines (debug info), `iT` hashes, `ia` everything.

**Analysis (`a`).** Nothing is analyzed until asked: `aa` (symbols and entry), `aaa` (calls, references, emulation, signatures; the usual choice), `aaaa` (experimental, slow). On a large binary raise `#:timeout-ms`, or analyze one function with `af @ addr`. `afl` lists functions (`aflc` count, `afll` verbose, `aflm` calls), `afi` info, `afn new @ addr` renames, `afvl` variables and arguments, `afvn new old` renames one, `afvt name type` retypes, `afs` signature, `afb` basic blocks, `afx` references of a function, `af-` undefines. Xrefs: `axt @ addr` to, `axf @ addr` from, `axl` all. `ao`/`aoj` decodes one instruction in detail, `ah*` are hints (`ahb 16 @ addr`), `av` vtables, `as` syscalls, `aav` values that point into maps. Graphs without the visual mode: `agf`, `agc`, `agC`, `agx`, `agr` take a format (`ascii`, `dot`, `json`, `json_disasm`, `gml`), as in `agf dot @ main`.

**Printing (`p`) and seeking (`s`).** `pd N` N instructions, `pD N` N bytes, `pdf` a function, `pdr` recursively over its graph, `pdb` a basic block, `pdsf` a function's calls and strings, `pi`/`pif` instructions only, `px N` hexdump (`pxw`, `pxq` words, `pxr` with references), `p8 N` hex bytes, `ps` a string, `pf fmt` formatted data (`pf xxS @ addr`, `pf?`), `pc` as a C array, `pv` a value, `ph md5 @!64` a hash or `ph entropy` of the block. `s addr` seeks for the following commands (`shu`/`shr` undo and redo, `sf` next function); prefer `@ addr`, which leaves the seek alone. `b N` is the block size.

**Flags, comments, types.** `fl` lists flags, `fsl` flagspaces (`fs symbols; fl` lists one, `fs *` selects all), `f+ name @ addr` adds, `f- name` removes, `fr old new` renames. `CC text @ addr` comments, `CCl` lists, `Cd N`/`Cs` mark data and strings. Types: `t` lists, `ts`/`tu`/`te` structures, unions, enums, `td "struct s { int a; char b[8]; };"` defines from C, `to file.h` loads a header, `tp s @ addr` prints memory as a type, `tc` dumps as C, `tx` type xrefs.

**Search (`/`).** `/z text` (string), `/x 9090` or `/x ff..33` (hex, `.` wildcards), `/v4 0x1234` and `/V4 min max` (values), `/a jmp rax` (assembled instruction), `/ad "push;mov"` (instruction sequence), `/r addr` (references; `/rc` calls), `/R pop` (ROP gadgets), `/cm` (crypto material), `/ce` (entropy), `/m` (magic). The range is `e search.in` (`io.maps`, `bin.sections`, `raw`, `dbg.maps`; `e search.in=?`), `search.from`/`search.to`. Hits become `hit.*` flags.

**Writing and patching.** Open with `#:write #t`, or `oo+` in an open session, or keep changes in memory with `e io.cache=true` (`wc` lists them, `wci` commits). `wx 9090 @ addr` hex, `wa "nop;ret" @ addr` assembles, `wao nop` and friends rewrite the current instruction (`wao?`), `w text`, `wz text`, `wv4 0x10` a value, `wff file` from a file, `wo*` block operations (`wox 0x41 @ addr @!4` xors). Check a patch with `pd`. Files are opened by `o file [addr]`, listed by `ol`, their maps by `oml`; `oo` reopens, `ood` reopens in the debugger.

**IL and emulation.** Rizin has two. **RzIL** is the current intermediate language (s-expressions): `aoi N` prints it for N instructions, `aoip N` pretty-printed, `plf` for a function, `agI` as a graph. Its VM: `aezi` initializes at the seek, `aezv reg value` sets a variable, `aezs N` steps, `aezse N` (`aezsej`) steps and lists every register, memory and pc change, `aezsu addr` runs to an address, `aezv`/`aezvj` shows the state. Stores fail on unmapped memory: map a stack first (`o malloc://0x10000 0x170000`). `La` marks the architectures that have RzIL with an `I` in its first column. **ESIL**, the older stack-based IL, is still what `aaa`'s emulation, `asm.emu` and the `ae*` emulator use: `aoe N` prints it, `e asm.esil=true` shows it in disassembly, `aei; aeim; aeip` set up its VM, stack and pc, `aes`/`aeso`/`aesu addr` step, `ar` reads and sets its registers (`ar rax=5`), `e asm.emu=true` annotates disassembly with emulated values. `aec`/`aecu addr` continue and can run forever: give them a `#:timeout-ms`. Neither VM runs imports or syscalls: emulate small pieces.

**Debugging (`d`).** Needs `#:debug #t` (or `ood`). `db @ addr` sets a breakpoint (`dbl` lists, `db- @ addr` removes, `dbc cmd @ addr` runs a command on hit, `dbw rw @ addr` a watchpoint), `dc` continues, `dcu addr` until an address, `dcr` until return, `dcs` until a syscall, `ds N` steps, `dso N` steps over, `dsu*` until a condition. `dr` registers (`dr rax=1` sets, `drr` with references, `drj`), `dm` memory maps (`dmm` modules, `dmi lib` symbols, `dmh*` heap), `dbt` backtrace, `dp`/`dpT` processes and threads, `dk sig` sends a signal, `dd*` file descriptors, `dts+` starts recording for reverse execution (`dsb`, `dcb`), `dg` writes a core dump, `doc` ends the debug session. Memory at `@ rsp`, `@ rip` and flags work as in static mode. `dc` blocks until the program stops: give it a `#:timeout-ms`; on timeout the program is interrupted and stays stopped in the debugger. The program's environment and files come from rz-run directives: `#:flags (list "-R" "setenv=A=1" "-R" "stdout=/tmp/out")`.

**Projects, scripts, remote.** `Ps file.rzdb` saves the analysis, `Po file.rzdb` (or `#:flags (list "-p" file)`) loads it. `. file.rz` runs a script of commands, `(name; cmd; cmd)` defines a macro and `.(name)` runs it, `$name=cmd` an alias. IO plugins open other things as targets (`Lo` lists them): `malloc://N`, `gdb://host:port` (a gdbserver; with `#:debug #t`), `http://`, `ihex://`, `srec://`, `zip://`, `dmp://` (Windows dumps), `winkd://`, `ptrace://pid`, `shm://`. `R+ tcp://host:port` connects to another rizin started with `Rt port`, `R fd cmd` runs a command there.

**Side tools** are separate programs: run them with `bash`, not here. `rz-bin` (file info without a session: `-I` info, `-i` imports, `-E` exports, `-s` symbols, `-S` sections, `-z` strings, `-j` JSON), `rz-asm` (`rz-asm -a x86 -b 64 'nop'`, `-d 90` disassembles, `-L` lists architectures), `rz-hash` (`-a sha256 file`, `-a entropy`), `rz-diff` (bytes by default; `-t functions`, `-t graphs` between two binaries), `rz-find` (`-s str`, `-x hex`, `-z` strings over files), `rz-ax` (base and unit conversion), `rz-gg` (small shellcode compiler), `rz-run` (run a program under a profile), `rz-sign` (FLIRT signatures; in a session `Fs file.sig`, `Fa`). Each has `-h`.
