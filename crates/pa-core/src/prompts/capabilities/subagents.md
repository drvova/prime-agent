# subagents: spawn, collect, and steer children

A target is a child's name or id, a spawn handle, or a subagent row. Results never come back from `rlm-spawn`: they arrive as agent messages, in files the child writes, or through `rlm-collect`.

- `(rlm-spawn prompt #:name #:model #:thinking #:cwd #:better)`: spawn a subagent one level deeper on `prompt`; returns its handle `{rlm_child_id, name, session_dir, model, queued_ms}` as soon as the child's session boots (under a large fan-out the spawn waits for a free boot slot; `queued_ms` says how long). `#:name` is required: unique among the child's siblings, short and descriptive. `#:model` (a `"provider/model"` selector) and `#:thinking` are inherited when omitted. `#:cwd` starts the child in that directory (it must exist; relative paths resolve against the session's working directory) and loads its project context. `#:better #t` first checks the prompt as a brief (see `better`). Raises when this session cannot create subagents
- `(rlm-collect [targets] #:timeout-ms)`: snapshots of direct children without steering anyone: one target or a list of them, none for every child. Each row is `{rlm_child_id, session_name, session_dir, status, settled, answer_preview, answer_text, error, duration_ms, tool_use_count, replied_since_task, queued_ms, check_status}` (absent values are left out); `status` is `"queued"`, `"running"`, `"done"`, `"error"`, or `"cancelled"`; `check_status` is `"none"`, `"pending"`, `"passed"`, or `"failed"` (the child's acceptance checks). `#:timeout-ms 0` (the default) does not wait; a positive one waits until the children settle or it passes, then returns the current snapshots, never an error
- `(rlm-list-subagents)`: this session's direct children, each `{rlm_child_id, active_session_id, session_id, session_name, session_dir, status, activity, tool_use_count, duration_ms, answer_preview, replied_since_task, progress_note, ...}`; `status` is `"running"`, `"completed"`, `"error"`, or `"cancelled"`
- `(rlm-delete-subagent target)`: delete one running or retained direct child; its last row
- `(rlm-abort target)`: stop a direct child's current turn without deleting it, to steer it (then send new instructions with `agent-message-send`): `{subagent, outcome}` with `outcome` `"aborted"` or `"idle"` (nothing was running)
- `(rlm-rename new-name #:session-id)`: rename this session, or a direct child given as `#:session-id` (a session id, a spawn handle, or a subagent row; never the child's name); the name the host settled on. Names are unique among siblings
- `(rlm-find-models [query] #:limit)`: models backed by the user's credentials that match `query` (default: all), at most `#:limit` (default 8): a list of `{provider, id, name, selector, image_input}`; `selector` is the exact string `rlm-spawn`'s `#:model` takes, `image_input` whether the model accepts images
- `(rlm-create-session prompt #:name #:model #:thinking #:cwd)`: create and prompt another depth-0 session; only for depth-0 agents backed by a daemon. Returns `{active_session_id, session_id, name, session_file, model}`
- `(rlm-progress-note message)`: report brief progress to the parent (at most 512 characters): `{accepted #t}`, or `{accepted #f, retry_after_ms}` when throttled (about one note per 10 seconds). The parent sees notes without needing a reply
- `(rlm-decide question options #:context)`: one short judgment call to your own model mid-cell; returns one of `options` (2 to 16 distinct strings) verbatim. The model sees only `question`, `options` and `#:context`, not the conversation, so pass what it needs. At most 8 per cell; each prints one `[decide]` line. Write a search/edit/test/retry loop as one cell and call it only where judgment is needed, never for what code can check
- `(better task #:cwd #:mode)`: a read-only helper on your own model rewrites `task` into the deeper prompt a top professional would ask for, grounded in the repository; returns the rewrite. `#:mode "brief"` instead checks a delegation brief against the repository from `#:cwd` (every path, name, and command must exist or run read-only), fixes what is wrong, and returns it unchanged when nothing needs fixing. A rewrite or brief ends with an `<acceptance>` block (`run: <command>`, `exists: <path>`, `grep: <path> <text>` per line); a prompt carrying one has the host run those checks when the turn ends, and a failed round arrives as a notice to fix and continue from
- `(better-checks)`: where the armed acceptance checks stand: `{status, checks, rounds, max_rounds, running, last}`; `status` is `"none"`, `"pending"`, `"passed"`, or `"failed"`; `last` is the latest round's evidence
- `(better-evidence handle)`: one check round's per-check results (`passed`, `reason`) by its `out:<id>` handle
