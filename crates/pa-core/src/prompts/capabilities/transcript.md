# transcript: the conversation, paged-out output, and compaction

- `(rlm-session-messages #:start #:limit #:role #:agent #:session)`: rows of a transcript, oldest first, each `{index, id, message}` with `message` the stored message (role, content, tool calls). Without `#:agent` or `#:session` it is this session's own transcript on the active branch, including the messages compaction summarized away (each compaction in place as a `compactionSummary` message). `#:agent` reads a family member's (a name, id, spawn handle, or subagent row); `#:session` reads a past session of this project (a search hit or its id), read-only; pass one, not both. `#:role` is a glob or a list of globs over `user`, `assistant`, `toolResult`, `custom`, `compactionSummary`, `branchSummary`, `bashExecution` (default `"*"`). Returns at most `#:limit` (default 10) of the matching rows from `#:start` on (default -10: the last ten; negative counts from the end). `index` is the position among the rows of that role; the page before `rows` starts at `(max 0 (- i k))` with `i` the first row's `index`
- `(rlm-session-count #:role #:agent #:session)`: how many transcript messages match `#:role`
- `(rlm-session-search query #:limit)`: past sessions saved in this project folder whose messages mention every word of `query`, most matches first (default 10): a list of `{session_id, title, created_at, updated_at, match_count, message_count, snippets}` with `snippets` as `{index, role, text}`. Read a hit with `(rlm-session-messages #:start index #:session hit)`. It never resumes, edits, or deletes a session
- `(rlm-session-tool-result tool-call-id)`: one tool result's full text; under context pressure, older large results are replayed as a head and tail with a pointer naming this call

A truncated output shows a handle, `[out:<id> · N chars · L lines · M chars not shown]`, after a preview of its text. The preview is chosen by information, not position: the first and last lines, error/warning/failure lines with their locations, then the lines with the rarest words, in their original order; `×N` after a line counts its repeats, `[… N lines …]` stands for lines left out, and `[… N noise lines …]` for lines this project's commands print on every run. An older result thinned from the request is previewed the same way. A cell keeps the first 262,144 bytes it prints: the preview and the handle cover those, and a note after the handle says how many bytes came later. The whole output is kept for the session, so page it instead of re-running the command. Line numbers are 0-based and each reply is capped near 16k characters. A handle without stored text (`evicted`, `not_stored`) raises from the three readers and says so.

- `(ctx-page handle #:start #:lines)`: lines from `#:start` (default 0), at most `#:lines` (default 200): `{handle, start, end, storedLines, text, truncated}`; read on with `#:start end`
- `(ctx-tail handle [n])`: the last `n` lines (default 200)
- `(ctx-grep handle pattern #:context #:max-matches)`: lines matching the regex `pattern` as `N:line`, context as `N-line`: `{matches, shown, text, truncated}`. `#:context` defaults to 2, `#:max-matches` to 50
- `(ctx-info handle)`: a handle's `state` and counts; never raises for a handle without stored text

Compaction replaces older history with a dense summary. It runs automatically when few tokens are left, on the user's `/compact`, or when scheduled here; the kernel's definitions persist through it.

- `(compact-status)`: context usage `{tokens, context_window, percent, scheduled}`; `percent` is unset right after a compaction until the next model response
- `(compact-run [instructions])`: schedule a compaction for when the turn ends: `{scheduled #t}`, or `{scheduled #f, reason}` when there is nothing to compact. `instructions` focus the summary. The harness then resumes the task with the summary plus recent messages. One request per turn is enough
