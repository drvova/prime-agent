# worktree: isolated checkouts, parallel hypotheses, and checkpoints

Give a subagent its own checkout so its edits stay out of yours: `(define wt (worktree-create "lane-a"))`, then `(rlm-spawn task #:name "lane-a" #:cwd (hash-ref wt 'path))`. Worktrees live under the agent dir, never inside the project, and belong to this session; remove each one when its work is merged. They need a git repository at the session's working directory. A worktree is `{name, path, repo, base, exists}`; wherever a function takes one, its name works too.

- `(worktree-create name #:base #:carry-changes)`: a new checkout of `#:base` (a commit, default `"HEAD"`) named `name` (1 to 64 letters, digits, `.`, `_` or `-`). Unless `#:carry-changes #f`, your uncommitted changes (staged, unstaged, untracked) are copied into it
- `(worktree-list)`: this session's worktrees of the current repository
- `(worktree-diff target)`: the worktree's changes since it was made (the carried changes excluded), as a patch string
- `(worktree-merge target #:strategy #:dry-run)`: bring the worktree's changes home: `{status, files, conflicts, branch, ok}`. `#:strategy "patch"` (the default) applies them to your checkout only when a `git apply` check passes; on a conflict nothing is applied and `conflicts` lists the paths (resolve them yourself, never by retrying). `"branch"` commits them to `prime-agent/worktree/<name>` instead. `#:dry-run #t` only checks. `status` is `"applied"`, `"clean"` (a dry run that would apply), `"conflicts"`, `"empty"`, or `"branch"`
- `(worktree-remove target #:force)`: delete the worktree; `#t`. Unmerged changes refuse the removal unless `#:force #t`
- `(rlm-hypotheses task approaches #:check #:timeout-ms #:better)`: try 2 to 6 distinct `approaches` to `task` at once, one child per approach in its own worktree; once the children settle, run `#:check` in each checkout and return the ranked table `{task, rows, winner, text}`: passing approaches first, then those whose child finished, then the smaller diff. `#:check` is required: a shell command run from each checkout's root (exit 0 passes), or a procedure taking the checkout path (an integer is an exit code, anything else passes unless `#f`). Each row is `{rank, approach, name, passed, child_status, check_exit, check_tail, answer_preview, diff, worktree}`; `diff` is `{name, files, lines, text, label}` with the whole patch in `text`. Every worktree but the winner's is removed; `winner` is the first row when it passed, else `#f`. Bring the winner home with `(worktree-merge (hash-ref winner 'worktree))`, then `worktree-remove` it. Children still running after `#:timeout-ms` (default 1800000) are aborted and their approaches fail. `#:better #t` first checks each child's brief

Checkpoints snapshot the workspace before a risky multi-file change, so it can be undone. They live in prime-agent's own shadow store (the one `/undo` uses), never in the project's git history, and belong to this session. They need the prime-agent daemon; headless runs raise.

- `(checkpoint-create [label])`: snapshot the files now: `{id, label, created_at}`
- `(checkpoint-list)`: this session's checkpoints, oldest first
- `(checkpoint-restore id)`: put the files back to a checkpoint of this session, after the user confirms the listed changes: `{status, restored}`; `status` is `"restored"`, `"declined"` (keep the files; do not retry), or `"no_user"` (nobody could confirm; nothing changed); `restored` counts the paths written or removed. Raises unless the user set `replCanRestoreCheckpoints`
